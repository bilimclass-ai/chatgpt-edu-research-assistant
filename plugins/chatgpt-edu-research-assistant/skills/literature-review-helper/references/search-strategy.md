# Search, access and screening

## Capability-aware plan

Inventory callable tools and supplied exports. Prefer the required databases when accessible, then discipline-appropriate discovery; supplement with broad indexes, citation chaining and authoritative repositories. Consensus can help when available but is not mandatory or a substitute for a required index. Crossref establishes deposited metadata, not Scopus coverage or peer-review quality. OpenAlex does not establish Scopus citation counts. Do not advertise an integration merely because it appears in instructions.

For Scopus/WoS-only requests without direct access, use an authorized user export if available. Otherwise explain the access limitation and distinguish publisher/catalog index evidence from direct article-level verification. Never claim a Scopus search was executed through ordinary web search. An unverified supplementary record cannot count toward a strictly verified-index minimum. A source may be scientifically useful yet fail that specific requirement.

Construct concept blocks with field synonyms, spelling variants and controlled vocabulary where supported. Translate concepts, not just words; distinguish observed indexed terms from proposed translations. Develop retrieval-sensitive queries before narrow precision filters. Record exact syntax for each database, including field tags, dates, language/type filters, coverage limits and cursor/page truncation. A few known papers can diagnose poor retrieval, but do not tune solely to confirm a preferred conclusion.

Include relevant foundational works, recent work and contrary/null findings; citation prominence never determines eligibility alone. Backward and forward chaining need their own log entries. Separate primary studies, reviews, preprints, official policy and contextual material. Screen sources about the target phenomenon rather than sources merely mentioning it.

## Search log and counts

For each execution record: query ID, database/tool, query string, language, filters, ISO date, records returned, records actually retrieved, source file/URL, status/error/retry, deduplication route. A displayed total may exceed records fetched; label it. Save enough identifiers to reproduce deduplication. After bounded retries according to tool limits, move to an allowed fallback; zero results are not a tool failure.

Maintain one screening record per report and stable study-family links. Distinguish:

- identified reports before deduplication;
- unique reports screened;
- full texts sought, obtained and assessed;
- eligible core reports and unique underlying studies;
- fully extracted core reports;
- supplements, excluded records and awaiting retrieval.

Do not invent a PRISMA flow from incomplete discovery counts. Full-text exclusions need reasons. Preserve mixed eligibility (e.g. verified database status for some years only) without silently treating missing information as positive.

## Identity and retrieval

Resolve DOI/PMID/ISBN/official identifiers against author/title/year/venue. Lack of a DOI is normal for some evidence types. Compare the downloaded document's first page/title/authors/DOI with the intended record; a plausible filename or index URL is not proof. Link corrections and retractions to their original record, and preprint/accepted/published versions to the same report family. Do not silently substitute a different document after a failed download.

Use publisher open access, authorized institutional access or legitimate repositories. Do not bypass paywalls or copy credentials. If only an abstract is available, keep it in a clearly labeled preliminary/supplementary queue unless the agreed protocol permits abstract evidence. Offer library retrieval or user-provided lawful PDFs when necessary. Complete independent extraction while these are pending.
